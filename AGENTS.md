# Project rules

- Correctness and executed evidence outrank speed.
- Never commit proprietary game/system files, secrets, SDKs, firmware, or generated distributables.
- Mark unavailable hardware, tools, assets, and tests `UNVERIFIED`; never infer a pass.
- Project-scoped Docker work is allowed; host package, driver, security, and service changes require explicit approval.
- Critical changes require build, focused tests, and independent review before merge.
- Keep task state and provenance durable under `tasks/`, `reports/`, and the status documents.
