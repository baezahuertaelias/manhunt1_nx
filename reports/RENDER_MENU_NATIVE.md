# Native menu adapter proof

Task: RENDER-MENU-NATIVE-001. This is the same synchronous module intended for opt-in game registration, linked to the portable executor using synthetic guest memory. Original-title rendering, level loading, performance, concurrent CPU/GPU access and physical Switch hardware remain UNVERIFIED. The module is not registered by this standalone fixture.

The adapter accepts the declared diffuse/texture×diffuse semantics, linear A8R8G8B8 surfaces, common transformed W between1e-3 and1e6 and sampled Q1. Sampled UV is bounded to absolute1e6texels across every transformed vertex before batch collection. Unsupported state/resources fall back before GPU work; unsupported transformed batches use the already-transformed CPU path. A diffuse-only draw ignores and sanitizes unused UV, including finite incoming UV that overflows after a stale texture dimension scale. Sampled textures have bounded RAM spans and P8 indices. Non-RC filtered texture draws explicitly fall back because the CPU non-RC path samples nearest regardless of filter state.

Each callback imports current guest pixels, waits for submitted GPU work, checks queue errors and reads back before returning. This preserves the existing synchronous guest-RAM ordering contract; it does not establish correctness under concurrent guest CPU writes. Device lifetime must cover all executor threads. A callback failure after accepted preflight terminates rather than silently dropping work or replaying a stateful vertex program.
