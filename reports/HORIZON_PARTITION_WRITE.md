# Private partition initialization write

HZ-PWRITE-001 removes the global Horizon `pwrite` emulation: its seek/write/restore sequence could race ordinary I/O sharing the descriptor. The current runtime subset has one `pwrite` caller, in `kernel_path.c` partition initialization. The caller opens `Partition0.img` locally with `O_WRONLY | O_CREAT`, builds one512-byte sector, writes it at byte0x800 and closes. The descriptor is never stored, returned or passed to other code between open and close; `xbox_build_partition_table` receives only the byte buffer. This explicit ownership permits checked seek/write in that caller. No generic atomic `pwrite` implementation is claimed.

The maintained0012 patch introduces one static helper around that existing operation: Horizon checks seek before write, while POSIX retains `pwrite`. The caller retains its short-write/error warning and immediate close. The broken global shim is removed from `horizon_compat.c`, so future missing Horizon `pwrite` dependencies fail at link instead of silently acquiring incorrect semantics. No guest instruction address applies: this is host partition initialization.

The focused script reconstructs pinned public upstream with maintained patches, extracts the exact authored helper with unique-boundary assertions, and compiles that helper into a shared host/Horizon fixture. Tests use synthetic files only: new-file extension, existing-file size and prefix/suffix preservation, offset placement, seek failure suppressing write, write failure preserving errno, short-write return and invalid descriptor. The negative control removes the seek and must fail. Fixtures check the helper, while full-game compilation and independent source review must verify caller wiring.

Final focused proof passes below. Full game build, boot, actual Switch hardware and general concurrent `pwrite` semantics remain UNVERIFIED.
